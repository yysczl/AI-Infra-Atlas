# 分布式训练排障清单

分布式报错经常只是最后一环的症状。先保存完整日志、启动命令、环境和拓扑，再缩小问题边界。

## 1. 先让问题可复现

- 固定代码、依赖、驱动、模型配置、数据版本和随机种子。
- 保存每个 rank 的日志，不只保留 rank 0。
- 记录节点、GPU、网卡、容器镜像和环境变量。
- 缩短到最小步数、最小模型与最小节点数，观察问题是否仍存在。

## 2. 建立对照组

- 单进程能否运行？单节点多卡能否运行？多机单卡能否运行？
- 去掉编译、混合精度、激活重计算等优化后是否仍出现？
- 相同代码在另一组节点或另一种放置策略下是否出现？

## 3. 按症状分支

### 显存不足

区分参数、梯度、优化器状态、激活、临时 workspace 和通信 buffer。检查分片是否真正生效，以及峰值出现的精确阶段。

### 吞吐不扩展

先测单卡基线，再看数据加载、主机瓶颈、集合同步、负载不均与 straggler。平均 GPU 利用率不能替代时间线。

### NCCL 超时或卡住

确认所有 rank 是否到达同一个集合通信，检查控制流是否因数据或错误而分叉。超时可能由上游计算、数据或异常 rank 引起，不应直接等同于网络故障。

### Loss 不一致

检查 sampler、全局 batch、梯度累积、随机状态、混合精度和数据顺序。性能对照实验必须保持训练语义一致。

## 4. 结束之前

写下根因证据、修复动作、验证结果，以及应该新增的监控或回归测试。不要只写“修改环境变量后恢复”。
