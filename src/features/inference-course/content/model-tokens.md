## 一段文字怎样进入模型

模型不能直接对字符串做矩阵乘法。输入首先经过 tokenizer，得到一串整数编号；随后用这些编号从嵌入表取出向量，才进入模型计算。**token ID 是索引，不是词义的大小或顺序。** ID 200 也不比 ID 100“重要两倍”。

下面先用一个完全固定的教学分词器。它只按空格切分，词表是我们手工指定的；它不是任何真实模型的 tokenizer，也不代表中文或英文应当如何切词。这样可以先把编号和张量的关系看清楚。

## 从 token 到整数编号

词表如下。用同一份词表编码和解码，才能保持编号的含义一致。

| token | ID |
| --- | ---: |
| `<pad>` | 0 |
| `<unk>` | 1 |
| 我 | 2 |
| 学习 | 3 |
| 模型 | 4 |
| 推理 | 5 |

输入“我 学习 推理”被切成三个 token，再转换为 `[2, 3, 5]`。空格在这个玩具例子里只是分隔符，不作为 token。下面的代码只需要 Python，可直接运行：

```python
vocab = {"<pad>": 0, "<unk>": 1, "我": 2, "学习": 3, "模型": 4, "推理": 5}
text = "我 学习 推理"
tokens = text.split()
ids = [vocab.get(token, vocab["<unk>"]) for token in tokens]
print(tokens)
print(ids)  # [2, 3, 5]
```

把输入改成“我 学习 编译器”，最后一个 ID 会变成 1，因为词表没有“编译器”。这说明 tokenizer 的处理方式会直接影响输入表示。真实系统常使用子词或字节级方法，不能把这里的未知词处理推到所有模型上。

## 编号变成向量之后，形状怎么变

假设玩具模型的嵌入维度是 4，那么词表大小为 6，嵌入表形状就是 `[6, 4]`。三个编号分别查三行，得到 `[3, 4]` 的表示。真实嵌入向量来自训练；下面只是为了理解查表而指定的数值。

```python
embedding = [
    [0, 0, 0, 0],  # <pad>
    [0, 0, 0, 1],  # <unk>
    [1, 0, 0, 0],  # 我
    [0, 1, 0, 0],  # 学习
    [0, 0, 1, 0],  # 模型
    [1, 1, 0, 0],  # 推理
]
ids = [2, 3, 5]
x = [embedding[index] for index in ids]
print(x)
print(len(x), len(x[0]))  # 3 4
```

加入 batch 维以后，单个输入的 ID 形状是 `[1, 3]`，嵌入输出是 `[1, 3, 4]`。三个位置可能使用相同 ID，但它们仍是三个独立位置；模型还需要位置信息区分顺序。

## 不同长度怎样组成一批

两个输入分别是 `[2, 3, 5]` 和 `[2, 4]`。如果使用补齐后的稠密张量，可以把短输入补为 `[2, 4, 0]`，于是 ID 张量是 `[2, 3]`，嵌入输出是 `[2, 3, 4]`。这里三个维度依次表示 batch、补齐后的序列长度、嵌入维度。

补齐位置不能被当成用户真正输入的内容。模型需要配套的 attention mask 等信息。真实生成时补齐方向、位置编号和 mask 需遵循模型接口；不要只把 0 拼到数组后面就认为可以正确生成。

| 输入 | 原始 token 数 | 补齐后长度 | 有效位置示意 |
| --- | ---: | ---: | --- |
| 我 学习 推理 | 3 | 3 | 1, 1, 1 |
| 我 模型 | 2 | 3 | 1, 1, 0 |

## 自己检查一遍

沿用上面的词表，把“模型 学习 我”编码，再写出它单独成批、嵌入维度为 4 时的两个形状。你可以先算，再运行前面的代码核对。

```atlas-answer
答案：ID 是 `[4, 3, 2]`；加入 batch 后 ID 形状为 `[1, 3]`，查表后为 `[1, 3, 4]`。调换词序通常不改变张量形状，但会改变编号顺序和后续计算结果。
```

真实 tokenizer 可能把一个词分成几个 token，也可能把标点、空格或特殊标记纳入编码。**计算上下文长度时应使用实际编码结果的长度，不能用字符数代替。** 换模型时，还要核对 tokenizer 版本和聊天模板；它们可能增加消息角色、边界等特殊 token。
