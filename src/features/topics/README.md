# 专题学习

这是原网站内各专题的统一入口。侧栏只显示“专题学习”，总览页根据 `catalog.js` 中已登记的模块生成卡片。目前发布“推理入门”，没有占位专题。

## 目录与路由

- `catalog.js`：专题的 ID、标题、简介、课程数、先修说明、学习方式、组件加载与上下文连接。
- `TopicArea.jsx`：专题总览、模块选择及父级导航。
- `routes.js`：统一地址生成和解析。
- `styles.css`：总览卡片和专题导航样式，限定在新区域的类名内。

`#/topics` 为总览，`#/topics/<topic-id>` 为某个专题，`#/topics/<topic-id>/<lesson-id>?section=...` 为该专题内的课程与段落。未知专题提供返回总览的入口。旧 `#/inference` 地址兼容到推理模块，不改写其已有进度或备份。

## 新增专题

1. 在 `src/features/` 中编写专题组件和内容，组件默认导出，接收 `route`（`id` 为本专题内的课程 ID，`section` 为段落 ID）。专题可自行组织课程或其他学习内容。
2. 在 `catalog.js` 的 `topicModules` 中新增一项。ID 使用小写字母、数字和连字符；填写标题、简介、课程数、先修与学习方式，`load` 返回组件的动态导入。
3. `getProps(context)` 返回组件需要的参数。通用 `openTopic` 可打开原站微课；现有推理模块还接收自己的学习状态。新专题有学习记录时，需要为其定义存储与备份方式，避免复用推理课的存储键。
4. 组件内使用 `topicsHref(topicId, lessonId, section)` 生成地址，样式限定在本专题范围。总览卡片、模块路由与父级返回入口自动接入，无需修改原侧栏或原学习路径。
5. 添加内容校验和必要的浏览器流程，运行根目录的 `npm run build` 与 `npm run test:ui`。

各专题独立加载正文与演示。原首页、学习路径、实验、笔记及 60 个主题继续使用原内容与全局样式。
